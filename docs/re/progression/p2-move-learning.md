# P2. Move learning [blue-verified; flow at runtime]

Part of [Progression](../progression.md). Addresses are `ov_0001::` unless plain (ARM9).


- **Which moves.** `02001AF4(out, species, level, IQ)` returns the moves the species learns at exactly `level` (up to 16). It walks the species' own learnset stream (level byte, then a 1- or 2-byte move id) and does not walk pre-evolutions. Species 0, `0x1A4` and `0x1A5` learn nothing. Four move ids (`0xEE`, `0xEF`, `0x110`, `0x162`) are dropped unless IQ (`info+0xC`) is at least 333 (thresholds read at runtime from the pointers near `02001C0C`). A move the monster already knows is not filtered.
- **Not this function:** `02001844` is the ground-side relearn list (callers `0203F880`, `020402C8`), not the level-up walk.
- **Per level** `02182E5C(_, entity, announce, interactive)`: for a non-team monster (`+6 != 0`) both flags are forced to 0. With `n` moves returned, **one** is learned: `DungeonRandInt(n)` picks it (the draw is made whenever `n != 0`, including `n = 1`) and it goes into the first free slot of an 8-entry local copy of the four moves at `info+0xF4` (6 bytes each), marked new. While the copy holds 5 or more moves (at most 30 passes): a team member (`+6 == 0`, partner included; the test is not "leader") with `interactive` set gets the forget menu `0216D77C(entity, list, 1, 0)` (cancel off; picking the new move declines it); anyone else goes to `02182A94`, which removes a uniformly random move with `DungeonRandInt(count)`, and the removed one can be the new move. The first four entries are written back; a kept new move prints the learned message when `announce` is set.
- **Callers:** `021833BC` only. `0216D77C` is also reached from `02182BD4`. 
- **Learn a move** `02182BD4(entity, move_id)` -> 0/1 (#572, [blue-verified] static). `info = entity+0x70`, move array at `info+0xF4`, 8 slots of 6 bytes (byte 0 bit 0 = exists, byte 1 bit 2 = new). It copies the slots to a stack buffer, puts the new move in the first free slot (new bit set), then while 5 or more exist and `info+6 == 0` shows a prompt (`0215439C`) and runs the forget chooser `0216D77C(entity, buf, 1, 1)`; a return of 0 (cancel) makes it return 0. At most 30 rounds. With fewer than 5 it copies back clearing the new bit and shows the learned message and jingle (`0213F50C`, 0x138). If the new move was the one forgotten it shows the did-not-learn message and still returns 1. `0216D77C` has two callers: `02182BD4` and the level-up `02182E5C`, so the TM path reuses the level-up forget chooser.
- **Caller** `02145CE4` only (call at `02145E48`), itself called twice from `02168774` (`02168A08`, `02169038`; `02168774` from the input loop `02166B10`). A TM-like item: item parameter to move id (`02007670`), refuses when the item flag 8 is set or `02007364` is non-zero, fills learnability byte `info+0x129` of the four party members (`02001A34`), picks the target with `0216AD10(0,1)`, consumes the item (`021415A4`) on return 1. [hypothesis] name "TM/learn-move item"; the item id is not tied. The `info+6 != 0` loop has no exit; [hypothesis] it is not reached for the player party. Not verified: runtime, item id.
- **Runtime (forced setup).** Species 158 learns a move at level 7 (3 moves after); with all four slots filled by the probe, `0216D77C` was entered with `r2 = 1`, `r3 = 0` about 150 frames after the level-up and the game waited for input. `02182A94` was not reached. The non-team removal branch and the menu's result handling are static only.
- **Runtime, #642 (blue-verified for what ran; not a menu result).** `levelup_probe.py` on a scratch copy of the EUR dump (SHA-1 `6f018873…`), `--menu-key a`, `b`, `new`, and `--force-nonteam` with `a`. Each run: 14 level-loop calls, one level-gaining call that matched the record dump (`all_match: true`), one learn call with `pre_valid: 3` and `announce: 1, interactive: 1`. No forget-menu call (`0216D77C`) and no removal call (`02182A94`) in any run. The learn had only three valid moves, below the five needed to open the menu, so the menu cases were not reached. The forced run (team flag forced to 1 at the level-loop entry) also left three moves, so the forced gate does not add moves and the removal stays unreached. Output summaries are the `summary` line of each run; the scratch outputs are outside the repo.
- **Forced runtime, #642 (FORCED gates; not natural).** `--force-moves` fills the species-4 learner's empty move slots (copies of slot 0) to four valid moves at its level-up entry; `--force-exp` raises its EXP to the level-7 threshold so one pass gains levels 6 and 7. Species 4 learns move 262 at level 7 (learnset from `crates/data` `parse_moves`, dumped by `levels_dump/src/bin/learnset.rs`). Result in all four runs (menu a, b, new; forced non-team with a): forced fill and EXP each fired once; the level 5 to 7 gain matched the record dump (`all_match: true`); two learn calls with `pre_valid: 4`; the level-7 learn added a move (five valid after). **No forget-menu call (`0216D77C`) and no removal call (`02182A94`) in any run,** even with five valid moves and the team flag 0 with interactive set. This contradicts the static reading above; either the hook address or the menu's gate on this path is wrong. Not resolved.
- **Sim:** one `DungeonRandInt` draw per level with a learnable move, always; one more per forced drop. The forget prompt is a shortcut until the sim has a prompt (use the wild rule). The level-up draws share the dungeon stream with the damage draws, and the pass runs after the turn's actions, so the order matters for traces.
