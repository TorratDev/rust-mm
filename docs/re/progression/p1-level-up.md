# P1. Level-up [blue-verified; runtime with forced EXP]

Part of [Progression](../progression.md). Addresses are `ov_0001::` unless plain (ARM9).


- **Where the total is written.** `AddExpPoints` (`02183F78`) only adds to `info+0x1C8` and sets `gDungeon+0xD` ([combat.md](../combat.md#defeat-and-experience)). `02183BB4` is the consumer: it runs when `gDungeon+0xD` is nonzero and clears it, loops over the 20 slots at `gDungeon+0x11364`, and for each slot with HP (`+0xE`) nonzero, `+0xD6` zero, `+0x1C8` nonzero and level (`+0x9`) not 100 does `info+0x18 += info+0x1C8`. It then prints the EXP message and calls `021833BC(_, entity, 1, 1)`, runs the evolution branch if `+0x11B` is set (P6.2), and zeroes `+0x1C8` and `+0x11B`. So level-up happens at turn-phase boundaries, not in the damage handler. Callers: 14 sites in the overlay (including `021409E4` and `02140A9C`, the turn loops) and ARM9 `0206E6C8`.
- **Per-level loop** `021833BC`. Returns 0 at once if the info is invalid or `+0x40` is `'J'` or `'G'`. Otherwise, from `L = level`: `L += 1`, stop at `L >= 101`, load the record with `02001C48`, stop when the record's EXP is above `info+0x18`. For each level gained: level = `L`; max HP (`+0x10`) and HP (`+0xE`) both add the HP gain, max HP is capped at 999 (literal at `02183640`), then HP is clamped to max HP; the four stat bytes at `+0x14..+0x17` each add their gain, capped at 255; then `021804CC` (skill bits) and `0218E3E4` (refresh, not read) run; then `02182E5C` (P2). Several levels can come from one call. The species used is `info+2`, the current species. No RNG anywhere. The code is the same for the leader, partners and wild monsters.
- **Loader** `02001C48(out, species, level)`: caches the species in a global; on a change it builds the `lvmpNNN` file name from the species number, loads it, unpacks it, and copies the 12-byte record at index `max(level-1, 0)`. Record layout: EXP total to reach the level (u32), HP gain (u16), then four byte gains, then two zero bytes. This matches `rescue_data::species::parse_level_data` (record `i` is level `i+1`). The byte order Atk, SpAtk, Def, SpDef is read from the order of the adds into `+0x14..+0x17`; the stat names are [red-hypothesis] ([`structs.md`](../structs.md) has `+0x14 atk[2]`, `+0x16 def[2]`). Stat at level `n` is the species base plus the sum of the gains for levels 2 to `n` (`02178E9C`, `02178EFC`, `02178F5C`).
- **HP rule.** Max HP and current HP rise by the same gain; there is no heal to full. **Runtime** (forced: the probe wrote a larger EXP total at `021833BC` entry): species 158 level 5 to 6, max HP +4 and HP +4, stats +3, +1, +1, +1; a total in the right range gave two levels in one call, with `02182E5C` once per level.
- **Natural level-up (#570) [blue-verified runtime].** No forced EXP or move list. `combat_inputs.txt` fights on the first floor (`levelup_probe.py`, scratch ROM copy, SHA-1 `6f01887356268de39085df01490347bbcc3aa330`; LEVELS from `cargo run --release --manifest-path verification/v7-trace/levels_dump/Cargo.toml -- <ROM> > <LEVELS>` (prints the `parse_level_data` records; scratch only); command `~/venvs/desmume/bin/python verification/v7-trace/levelup_probe.py <ROM> <LEVELS> <OUT> --inputs verification/v7-trace/combat_inputs.txt --frames 20000 --menu-key a`; output SHA-256 `05f47dcd876ed4e4923c9f6c236500364c4b7aefb1f4f8c76cc8959a70b5fcd8`, re-run 2026-11-23, see the re-run note below). Each run earns EXP through `02183BB4` (pending EXP at `+0x1C8` moves the total at `+0x18`), then `021833BC` runs. Two calls raised a level, one each for species 158 and 4 (the partner), from level 5 to level 6. Each call entered `02182E5C` once, the one level gained. For each level-up the record check passed: the EXP total met the level-6 threshold (record 5 of `lvmp` for each species, [blue-verified runtime] as the `parse_level_data` record; the table values are not in the repo) and max HP and HP both rose by the record's HP gain, the four stat bytes at `+0x14..+0x17` rose by the record's attack and defense bytes, in that order.

- **Raise by N** `02183994(_, entity, n, announce, flag)` (wrapper `021465C8`; five more callers `021A19B0`, `021A2480`, `021A2DC0`, `021A3940`, `021A47E0`): level = `min(level + n, 100)`, sets `info+0x18` to the record's EXP, calls `021833BC`, then `02183720` for the stat difference. It is an effect, not the EXP path. Callers (#572, [blue-verified] static: export xrefs and the wrapper's instructions; no runtime run). Six call sites, signature `(ctx, entity, n, announce, flag)`:
  - **Joy Seed** (item effect 0x4A): wrapper `021465C8`, called from the item switch `02146880` at `02146F10`; call at `021465DC` with n=1, announce=1, flag=1. The only item caller.
  - Five scripted cases of the dispatcher `021A02AC` (switch on byte gDungeon+0x34AD, called once from RunDungeon_Async at `0206E4B4`): functions `021A1944` (case 9), `021A240C` (0xC), `021A2D50` (0xF), `021A38B4` (0x14), `021A476C` (0x19); call sites `021A19B0`, `021A2480`, `021A2DC0`, `021A3940`, `021A47E0`; announce=0, flag=0 (silent: no message, no stat-difference display). n is a signed short read through a literal pool pointer, 20, 20, 20, 10, 10 in the decompressed overlay; keep it a table lookup, not a constant. Each case takes the leader, picks an entity with `0219F534(k)`, tests an event flag with `0219DA60`; if clear it raises the level, if set it removes the entity (`021778F4`).
  - Which story events those cases are: [hypothesis] scripted-floor events; not identified (not items).
  - Nothing happens when the level would not change or `info+0x40` is 'J' or 'G'. The stat-difference message (`02183720`) needs a non-zero `021833BC` result, `info+6 == 0` and announce != 0; the stat-delta array at `02183BA0` is filled whenever the level loop ran and `info+6 == 0`.
- **Level down** `02183120` (called by `021836C8`) loops down and subtracts the gains; not needed now.
- **Level 100.** `021833BC` stops at 100, `02183BB4` skips level-100 members, `AddExpPoints` returns at 100, `02183994` clamps at 100. No other cap branch.
- **Sim:** `combat::add_exp` reads `levels[level]` as the next threshold, which matches. Missing in the sim: the gains, the 999 and 255 caps, and the HP bump (shortcut noted in [combat.md](../combat.md#defeat-and-experience)).
