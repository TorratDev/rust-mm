# P7. Personality quiz and starter [blue-verified, static]

Part of [Progression](../progression.md). Addresses are `ov_0001::` unless plain (ARM9).


- **State machine** `0206C6E4` (details in [`rng.md`](../rng.md), #170). The tracker (200 bytes) is the global at `020E077C`. Eight questions are asked: `+0x40` counts up and the ninth pass opens the gender menu. Case 4 reveals nature and starter; cases 5 to 14 are dialogue, partner menu, nickname, end.
- **Questions.** 55 records (plus a bonus record at `020B84F4`, index 55) behind the pointer array at `020B9848`. Record (12 bytes): text id (u16), zero (u16), answer menu pointer, effects pointer. Answer entries are 12 bytes, ended by a sentinel; the value is the effects row index. Effects: `rows[value][13]` bytes with **stride 13** (this settles the "13 or 16" open point in rng.md). Category table `020B970C` (55 bytes, 14 categories): once a question is picked, every question of its category is marked used, so the 8 questions come from 8 distinct categories. The pick is `RandInt(0x37)` in a retry loop until the flag is not 1.
- **Bonus question.** An answer value of 99 (one answer of question 9) sets `+0x44 = 0x37` and returns to state 1 without counting a question or adding effects; the bonus record then plays.
- **Score and nature.** `totals[i] += effects[value][i]` for 13 words at `+0x4C`. `0206C394`: `n = RandInt(13)`, then 12 steps of `u = (u+1) % 13`, `n = u` when `totals[n] < totals[u]` strictly. The maximum wins; a tie goes to the candidate met first walking up from the random start, so the draw is only a tie-break.
- **Gender** is asked (a menu after the 8 questions), stored at `+0xB8` and in the options byte; it is not derived.
- **Starter** is the u16 at `020B96D8 + nature*4 + gender*2` (13 natures by 2). **Partner:** 10 candidate species at `020B993C`, filtered by `0206C978` to drop any candidate that shares a non-zero type (species record bytes `+0x13`, `+0x14`) with the starter; the starter is always excluded. The choice is written to `+0xA` of the tracker. Tables not copied.
- **RNG.** Both draws are the global generator (`RandInt`, `02011968`), not `DungeonRand`. The state at quiz time depends on every earlier draw, so a sim needs a seed state to match a retail result. Case 15 also reseeds the Mersenne Twister (not used by the result).
- **Hand-off (#575):** the tracker is copied to `020DF920` at the teardown and read by `0201E020`; the roster writer `02003510` gets the starter and partner ids (P7.1 golden trace, P7.2 record fields). The starting level is not located. The hero's roster record is in slot 209 after the full dump (P7.2) [emulator-verified].
- **Not verified:** the starting level; the move ids; the other record fields (P7.2); personality names.

## P7.1 Golden trace of the quiz and the hand-off [emulator-verified, #575]
Probe `verification/v7-trace/personality_quiz_probe.py` (py-desmume on a scratch ROM copy, `boot_to_dungeon.txt` inputs, 10800 frames). The trace output stays outside the repo; only the results below are recorded. One natural new-game run with one set of answers and one gender; other answers were not tried.
- `0206C590` ran 9 times (frames 3043 to 3703, return `0206C778`). The tracker is `*020E077C` (a heap pointer, not the global itself). `+0x40` counts 0 to 8 and `+0x44` holds the drawn question. The ninth call is the gender-menu pass. 8 distinct questions were drawn, as in P7.
- `0206C394` ran once (frame 3743). The 13 totals at `+0x4C` are **u32** words (stride 4, not u16). The maximum is unique. After the call, the nature at `+0x48` holds that index and the starter at `+8` holds a species id (gender 0).
- The partner at `+0xA` is set by `0206C1FC` (P7). It reads back as the same partner id at the teardown copy.
- The teardown call `0206C684` to `0201E17C` (call `0206C6B8`, return `0206C6BC`) copies the tracker to the hand-off block `020DF920`. `0201E020` is entered from `0213A7C8` (call `0213A7C4`) and reads the starter at `020DF924` and the partner at `020DF926` with the same values as the tracker [emulator-verified].
- The tracker pointer is 0 by the time `0201E020` runs (freed). Only `020DF920` carries the result.
- The quiz ids reach the roster writer `02003510` unchanged: the call from `0201E070` (return address) passes the starter, with isHero 1; the call from `0201E0E0` passes the partner, with isHero 0 [emulator-verified, arguments].
- Rerun with the full roster dump (no 64-slot cap, 10800 frames, the same boot inputs): the same draws, nature (5), starter (158) and partner (4) as above; both roster writes land in the dump (P7.2) [emulator-verified]. Output stayed in the scratch directory.

## P7.2 Roster records, starting level, moves and IQ [blue-verified static; partly emulator-checked]
- **Record base.** `02003510` writes into the record array at `*(*020036E0)`, the slot count is `020036E4` (static, from the decompile of `02003510`). The runtime read gives the same pointer at `*020DDF84` (`0x020E0F8C` in the golden run) and the count **413** [emulator-verified, the probe dumps all 413 slots]. The slot is the first one whose flags bit 0 is clear and whose area (`02009230(i)`) equals the species' area byte (`species record + 0x16`, via `*020036DC`). If no slot matches, the function returns without writing. Then `*020036E8[area] = 1` and `020115BC(species)` run. The record is 0x40 bytes, copied from a stack buffer [blue-verified static, `02003510`].
- **Record fields.** Confirmed by the full dump (hero slot 209, partner slot 54) [emulator-verified]: flags u16 = 3 at +0; byte +2 = isHero (1 hero, 0 partner); byte +3 = 1; byte +4 = 0x40 for the hero, 0x41 for the partner; u16 species at +6 (158 and 4, the quiz ids); u16 **IQ at +0xA = 1** for both. The offsets come from the stack buffer layout in the decompile of `02003510` [blue-verified static]. Still hypothesis, not confirmed by a dump: u16 at +0xC from `020022C0(species)`; types and abilities from `0200224C` and `0200222C` (+0xE to +0x11); skill bytes from `0200429C`; four move slots from `020016B4`.
- **IQ 1.** Set by a constant in `02003510`. Read at +0xA in both records of the full dump [emulator-verified, hero and partner].
- **Moves.** `020016B4` calls `02001AF4(buf, species, level 1, cap 0x3E7)`, the level-1 learnset filter (P2). The cap value 0x3E7 is observed at runtime as the `02001AF4` argument r3 [emulator-verified, argument]. The partner's record has move bytes written; the move ids are not recorded here. A fixed fallback move is used when the level-1 list is empty [blue-verified static, `02003510` callee path].
- **Starting level: not in the record.** `02003510` stores no level field. The level-1 argument is the learnset filter only. The starting level of the hero and partner is **not located** (no emulator read of a level field; the dump checked the record bytes only). Open.
- **Hero record found.** The earlier 64-slot dump could not see the hero's record, because it sits in slot 209. The full dump after the hero's call (species 158) shows slot 209 live: flags 3, isHero 1, +4 = 0x40, species 158 at +6, IQ 1 at +0xA [emulator-verified]. After the partner's call, slot 54 is live too (flags 3, isHero 0, +4 = 0x41, species 4, IQ 1), and slot 209 is unchanged. The slot rule (the first free slot whose area matches) is static [blue-verified static]; the area value of species 158 and the `02009230` mapping were not read at runtime.
