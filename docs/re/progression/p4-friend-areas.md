# P4. Friend areas [blue-verified, static; runtime results tagged blue-verified runtime, the rest unverified]

Part of [Progression](../progression.md). Addresses are `ov_0001::` unless plain (ARM9).


- **Species to area.** Species record byte `+0x16` (reader `020022DC`, [blue-verified static]) is the area id (0 to 57). Byte `+0x12` (reader `02002288`, [blue-verified static]) is the friend flag: eleven species have it nonzero, and they pass the recruit gate without their area (P3 gate 4). **Runtime (run 1, fresh save, first floor): base resolved and count measured as 15, not 11.** Over all 424 records the friend flag is 1 on 15 species and 0 on 409 (`out.json` sha256 `6a3e67be8fb6aa21`, first 16 hex): species 144, 145, 146, 274, 276, 387, 408, 409, 410, 411, 412, 414, 417, 418, 419. The static count of eleven does not match this runtime count; the difference is not explained yet (the static count may have used a different reader or a subset). The reader literals at `020022A0` and `020022F4` both load the cell `020DDF80`; `*020DDF80` is the species base. The last attempted reader-pointer chain produced `0x06609AD0`. That address is **not outside memory**: [`turns.md`](../turns.md) puts the `monspara` copy in ARM9 VRAM at `0x06608000`, with the first record at `0x06609AD0`, and the ARM9 VRAM window is `0x06000000` to `0x067FFFFF`. The earlier "outside main RAM" rejection tested a main-RAM-only range, but the table is not in main RAM; that rejection is corrected here. The base is therefore resolved by the runtime read plus the static copy address, but a runtime `+0x12` count is still **unverified**: no probe output with the corrected window is recorded, so the count of eleven remains static-only. The probe now counts all 424 records and reports the base window. Record stride `0x48` and offsets `+0x12`/`+0x16` are static reader evidence. Meaning of the flag [red-hypothesis] "recruitable without the area".

- **Where a recruit goes.** In the dungeon it is only a 0x54 party record. At the end of the dungeon `02178068` builds a per-area list: with room, each recruit is inserted with `02003130`; with a full area, a selection screen (`02175178`) makes the player release monsters (old ones or the recruit), then the survivors are inserted. `02003130` adds nothing if the area is not owned or its block is full, and marks the species seen (`020115BC`, [red-hypothesis]). A guard on entries with `+4` equal to `0x44` or `0x45` re-prompts; it is not understood (low).
